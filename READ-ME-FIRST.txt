SMS — you do not have to sign up for anything
===============================================================================

Good. Don't. I went back through the product and checked what actually depends on a
text message leaving the server. The answer is: nothing.

  · signing up completes on the emailed link (Resend is live and working)
  · booking a rider, offers, counters, chat, masked calls — all in-app, no SMS
  · a rider who is offline misses the offer SMS, but the offer is still in their app

So SMS is a nice-to-have sitting on top of a working product, not a hole in it. Leave
it off. That is a legitimate answer, not a shortcut.

BUT I FOUND SOMETHING WHILE CHECKING, AND IT WAS REAL
-------------------------------------------------------------------------------
The app was still OFFERING phone confirmation on a deployment that cannot send texts.
Three places:

  · Settings: a "Verify now" link
  · every portal: a "Your phone number is not verified" banner that could never be
    cleared, no matter what the customer did
  · the verification screen: a 6-digit code box under the words "we sent a 6-digit
    code" — and in production the API deliberately does not return the code, so the
    customer sat there with nothing to type

In development the code is shown on screen, so this never bit you. In production it is
a dead end that quietly says the product is broken.

That is fixed now:

  · the API refuses out loud (503, "nothing was sent, and it is optional")
  · Settings says "Not confirmed" instead of a link that goes nowhere
  · the banner stays quiet
  · step 2 of verification explains, in two sentences, that the step is off and that
    email is all the account needs
  · the customer home badge says "Phone on file", not a warning that never clears

The moment you DO add a provider, all of it turns itself back on — the browser reads
the API's own health block, which has always said whether SMS is really configured.

ON TERMII, HONESTLY

Email cost you a DNS records afternoon. SMS will cost you more, because it is not a
technical step at all: it is a business-verification step. An account, a sender ID a
human approves, and the DND route that Termii switches on by hand after you email
support. Days, sometimes weeks. There is no self-serve way to reach every network —
anyone who tells you otherwise is selling the generic route, which silently fails on
do-not-disturb numbers, which in Nigeria is most of them.

So: do it when a customer asks for texts, or before you run a paid-marketing push.
Not before launch. I have written it all down in documentation/SMS-SETUP.md so it is a
checklist when that day comes rather than a research project.

If you ever want it faster than Termii's review, say so and I will add a second driver
for a provider that issues OTP sender names at sign-up (Robase, Arkesel, Sendar). That
is roughly forty lines in one file — worth doing the day you decide, not before.
