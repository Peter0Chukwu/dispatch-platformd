TWL — the reset link worked; the full stop broke it
====================================================

Commit: 43db649   (previous: cde5830)

WHAT YOU SAW
------------
The reset email arrived with the right address this time, and the link inside was
followed by a full stop because it sat at the end of a sentence:

  .../reset-password?token=3xCfKl3MuCo4qPeh5VZur4K80n05ML_T3gv2dcVMXuM.
                                                                      ^
Mail apps treat that full stop as part of the link. So the token the page received
ended in ".", which is not part of any token — and the API correctly said the link
was invalid. Not the same fault as before, one layer down.

WHAT CHANGED
------------
1. The link now stands on its own line in both emails (reset and verification),
   with no punctuation touching it.
2. The server now recovers the token from whatever arrives — a bare token, a whole
   pasted link, a link with a full stop, a token with a trailing space.
3. A real bug found while in there: a regex reused with .test() meant every other
   link in an HTML email was left as plain text instead of a clickable link.
4. Trailing punctuation is no longer swept into the href.

Six tests added (99 total, no database). Typecheck and production build clean.
