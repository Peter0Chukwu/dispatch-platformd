TRADERS WELFARE — SIGN-IN FIX (CORS)
====================================

WHAT THIS IS
  The fix for "Could not sign you in / Something went wrong on our side.
  Reference: unknown" on the staff page. Commit a3e2bfc, on top of 8f2bb0f.

WHY IT WAS BROKEN (in one paragraph)
  A browser sends an Origin header on every non-GET request, even when it is
  calling its own server. Our CORS allowlist did not contain the deployment's
  own URL (it still said localhost:5173), so the login POST was treated as a
  foreign site. The code threw an error at that point — and an error thrown that
  early comes out as a 500 with no request id, which is why the reference said
  "unknown" instead of a proper code. Nothing was wrong with the account, the
  password, the database or the API. I proved it against the live server: the
  same request with no Origin header returned 201; with Origin it returned 500.

APPLY IT (VS Code Source Control tab first)
  1. Unzip over C:\Users\USER\Documents\dispatch-platform.
  2. Source Control: 6 changed files (cors.ts and cors.spec.ts are new).
  3. Commit with COMMIT-MESSAGE.txt, then Push.

TERMINAL
  git apply --stat sign-in-fix.patch
  git apply sign-in-fix.patch
  git add -A && git commit -m "cors: the app's own origin can always sign in"
  git push

MEANWHILE — UNBLOCK IT WITHOUT WAITING FOR A REDEPLOY
  In Northflank, on the API service (twl-frontend), add to the environment:

    CORS_ORIGINS=https://p01--twl-frontend--glzb7542cqkx.code.run

  and also set, if it is not already right:

    FRONTEND_URL=https://p01--twl-frontend--glzb7542cqkx.code.run

  Save, let it restart, then sign in. Type the value bare — no quotes.
  Once this patch is deployed, you will not need CORS_ORIGINS for your own
  host any more, only if the web app and the API ever live on different hosts.

CHECK IT
  curl -s -o /dev/null -w '%{http_code}\n' -X POST \
    https://p01--twl-frontend--glzb7542cqkx.code.run/api/v1/auth/login \
    -H 'Content-Type: application/json' \
    -H 'Origin: https://p01--twl-frontend--glzb7542cqkx.code.run' \
    -d '{"identifier":"admin@dispatch.test","password":"wrong-password","audience":"ADMIN"}'

  Expect 401 (that is "wrong password", which is correct and proves the request
  got through). 500 means the old build or the old environment value is still
  in place.
