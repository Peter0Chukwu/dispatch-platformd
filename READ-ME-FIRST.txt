TRADERS WELFARE — SAVED PLACES (ADMIN SCREEN)
=============================================

WHAT THIS IS
  Admin → Saved places. The pickup/drop-off list the booking form offers is now
  a database table you maintain yourself. A new neighbourhood is a row, not a
  deploy and not a code edit. Commit f116cc5.

HOW YOU RUN IT — THREE STEPS, ONCE
  1. Update the code (below).
  2. Run the migration, because it creates the table:
         cd backend && npx prisma migrate deploy
     On Northflank, this is the same step you ran when the staff invites shipped.
  3. Rebuild + redeploy the web service (there is a new admin page), and restart
     the API.

WHAT YOU DO AFTERWARDS, FOREVER
  Admin → Saved places → "Add a place"
    Name        Ikpoba Hill
    Address     Benin-Auchi Road, Ikpoba Hill, Benin City
    Landmark    By the Ikpoba River bridge
    Latitude    [press "Find coordinates from the address", or type 6.3565]
    Longitude   [5.6691]
    Order       lower numbers appear first

  Save. It is on the booking form on the next keystroke. No deploy, no restart.
  "Hide" takes a place off the form and keeps the record; "Restore" brings it back.

WHAT IF THE MIGRATION HAS NOT RUN YET
  Nothing breaks. The API logs one warning and the booking form falls back to the
  twelve Benin City places it shipped with. The admin screen shows the database
  error until the migration runs.

APPLY THE CODE (VS Code Source Control tab first)
  Unzip over C:\Users\USER\Documents\dispatch-platform. Stage the 10 changed
  files and the 5 new ones, commit with COMMIT-MESSAGE.txt, push. Terminal:
      git apply --stat saved-places.patch
      git apply saved-places.patch
      cd backend && npx prisma migrate deploy && cd ..
      git add -A && git commit -F COMMIT-MESSAGE.txt && git push

  No new dependency. One new table. One new admin page.
