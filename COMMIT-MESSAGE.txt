maps: Geoapify, so maps work without a Google Cloud account

Google wants a billing account before it answers a single request, and that
account was a dead end. Geoapify does not: no card, commercial use allowed with
attribution, 3,000 credits a day, and ONE key for suggestions, geocoding,
reverse geocoding, routing and the map tiles.

MAPS_PROVIDER=GEOAPIFY is now the recommended setting. The adapter follows the
same shape as the Google one, so pricing, dispatch radii, ETAs and the booking
form are untouched:

  · suggestions  GET /v1/geocode/autocomplete   (filter=countrycode:ng)
  · typed address GET /v1/geocode/search
  · a pin       GET /v1/geocode/reverse
  · a route     GET /v1/routing?mode=drive     → metres and seconds

Suggestions arrive already geocoded, so picking one costs ONE request instead of
Google's autocomplete-plus-details pair. GeoJSON is longitude-first; a swap would
place every pickup in the Gulf of Guinea and nothing downstream would notice, so
test/maps.geoapify.spec.ts asserts the order, the Nigeria filter, the metres and
seconds conversion (including an account configured in miles), and that every
failure path falls back to the stub. Nine cases.

The live map moves from Google's JavaScript API to Leaflet over Geoapify tiles —
one small open library instead of a vendor script tag, dynamically imported so
only screens that show a map pay for it, with the "Powered by Geoapify" and
OpenStreetMap credits the free plan requires. Markers are circle markers, which
need no icon assets and cannot appear as broken images. Without a key it still
falls back to the schematic, which draws the same coordinates and says so.

The product copy follows: the picker says "Address suggestions as you type"
instead of naming a vendor, the tracking card says "Road route" for any real
provider, and the admin city view badges STREET MAP or OUTLINE.

documentation/MAPS-GEOAPIFY-SETUP.md is the click-by-click; CREDENTIALS-SETUP §3
now leads with Geoapify and keeps Google as 3b. VITE_GEOAPIFY_API_KEY is wired
through Dockerfile.web and docker-compose as a build arg, because that is the
step people miss.
