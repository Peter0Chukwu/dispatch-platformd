email: the link stands alone, and the token is read back properly

The password reset arrived with its link working but the sentence's full stop
attached to it — "?token=…VMXuM. If you did not ask" — and a mail client that
auto-links takes that full stop into the URL. The token then carried a character
that was never in it, and the API answered that the link was invalid. Both email
bodies now put the URL on its own line with no punctuation touching it.

That is only half of it, because people will still paste the whole link, or a
link with the full stop. cleanToken() now recovers the token from whatever they
send: takes the part after token=, stops at the first space, and keeps only
base64url characters. Applied on the server, so it does not matter which screen
the request came from.

While in the renderer, a real bug: .test() on a /g regex advances lastIndex, so
every other link in a message was left as raw text. Replaced with a split that
needs no state, and the href no longer swallows trailing punctuation.

Six tests added (99 total, no database); typecheck and production build clean.
