maps: talk to the Google services that still exist, and stop narrating the internals

Google stopped selling the legacy Places, Directions and Distance Matrix APIs on
5 October 2026, so a Cloud project created today cannot enable them. Every
deployment of this platform starts as a new project, which means the adapter in
MapsService would simply have failed with LegacyApiNotActivatedMapError and
quietly priced every delivery from the stub table.

Address suggestions now come from Places API (New) — places:autocomplete for the
predictions, then places/{id} with an X-Goog-FieldMask of
id,displayName,formattedAddress,location for the coordinates, so Google bills
three fields instead of the whole place. Distances come from the Routes API
(directions/v2:computeRoutes) with a DRIVE, traffic-unaware, metric request, and
the protobuf duration string ("842s") is parsed into minutes. Geocoding was not
retired and is untouched. The stub fallback stays: a Google outage or a key
missing an API logs a warning and prices the booking anyway.

Covered by backend/test/maps.google.spec.ts, which asserts the URLs, the header
auth, the field masks, the region restriction and the duration parsing, and that
both paths degrade to the stub on an error response.

Also: the last of the engineering notes are gone from the product. The banner now
says "Test mode · no real money moves and no real messages are sent"; the
tracking card says "Estimated route" instead of "maps key not configured"; the
price breakdown says "estimated distance"; the picker says "Popular Benin City
locations"; and the empty map says when the rider's position will appear.
documentation/CREDENTIALS-SETUP.md now lists the four APIs a new project can
actually enable.
